# Skill OS 使用说明：项目接入与工程 Workflow

## 1. 产品边界

Skill OS 是项目控制平面，负责：

- 绑定一个项目目录并只扫描该目录。
- 发现项目本地 Skill 和 Workflow 资产。
- 预览并应用推荐的 `project-engineering-workflow`。
- 查看项目 Profile、架构摘要、扫描状态、连接目录、心跳和运行证据。
- 查看 Skill 命中、Tool 调用、Token、验证和会话链路。

Skill OS 不会替代 Codex/Claude 执行代码，也不会强制模型调用某个 Skill。项目内是否触发 Skill，取决于目标目录中的 `AGENTS.md`、`.agents/skills` 和实际会话目录是否匹配。

## 2. 第一次绑定项目

1. 启动桌面端，在“项目管理”点击“绑定项目”。
2. 在系统目录选择器中选择项目根目录，例如：

   `/Users/bing/MyJob/Project/Codes/mall_side/Backend/autovado-goods`

3. 检查弹窗中的目录路径，点击“扫描并绑定”。
4. 等待扫描完成，确认项目列表出现：项目名称、路径、扫描状态、扫描时间和 Skill 数量。
5. 点击项目列表的“查看”图标进入项目详情。

不要选择电脑上层目录，也不要把多个项目目录合并成一次扫描。

## 3. 空项目应用推荐 Workflow

在项目详情或扫描结果中：

1. 点击“预览推荐 Workflow”。
2. 检查待创建文件、已有文件、冲突文件和保留文件。
3. 确认没有需要覆盖的业务文件后，点击“应用推荐 Workflow”。
4. 等待应用完成，再重新扫描项目。
5. 确认 Workflow 状态为“已应用/就绪”，并确认项目 Profile 已生成或刷新。

已有 `AGENTS.md`、项目规范或 Workflow 文件时，必须先看冲突预览。出现冲突不要直接覆盖，先处理冲突后再次预览。

## 4. 让 Codex 真正进入项目 Workflow

应用 Workflow 只是把规则放入项目目录。要触发它：

1. 在 Codex 中从目标项目目录新建任务。
2. 确认当前任务目录与 Skill OS 项目路径完全一致。
3. 提交清晰的需求，不要从其他父目录启动任务。
4. 对标准或受控任务，等待需求、影响范围和计划确认。
5. 用户确认后，Workflow 才进入实施阶段。

项目内的标准链路是：

```text
Project Profile
→ 需求与影响
→ 设计/技术方案
→ 计划与 TASK 拆解
→ 用户确认
→ 实施
→ Review / Test / Verification
→ 用户验收
```

## 5. 设计、计划、实施分别在哪里

- 设计：需求边界、项目架构、影响范围、技术决策，记录在 `spec.md` 和 `plan.md`。
- 计划：`ITEM-*`、`TASK-*`、依赖、完成条件、验证证据，记录在 `plan.md` 和 `tasks.md`。
- 实施：进入 `executing`，由项目级 Skill、前端/后端规范和代码生成规则驱动实际修改。
- 验证：进入 `verifying`，执行构建、测试、审查和影响到证据映射。
- 验收：输出 `delivery-summary.md`，状态进入 `awaiting_user_acceptance`。

简单低风险任务可以走 fast 通道；跨模块、数据库、安全、架构和外部影响任务应走 controlled 通道。

## 6. 查看项目是否真正连通

打开项目详情，重点看：

- 项目 Profile：应为“已就绪 · 新鲜”。
- Workflow：应为“已应用/就绪”。
- Codex 连接：检测目录必须等于期望目录。
- Adapter 就绪诊断：安装状态、目录连接和技能观测必须分别看；“推断已调用”不等于精确调用。
- 心跳：能看到最近运行、调用次数和 Token。
- 项目技能：能看到扫描出的 Skill 列表。
- 会话链路：能看到路由、Workflow、Skill、Tool、验证和响应证据。

可以直接在“会话链路”的搜索框输入 Codex/Claude 会话 ID。列表会显示同一个 Session 下的多个 Turn，详情顶部会显示完整会话 ID；点击时间线中的 Skill 名称可打开只读快捷查看。

如果显示“已配置待连接”或“未检测到项目任务”，请在目标目录新建一次 Codex 任务，再点击“刷新运行”。

“运行监控”内的“Adapter 就绪诊断”可重新检查这三个状态。展开“精确观测接入预览”后，点击“前往导入遥测”，应用会关闭项目详情并定位到“分析 / 遥测”的文件选择区域；在那里选择已脱敏的 Protocol 1.0 JSONL 文件并确认导入。关闭预览或项目详情即可取消，不会写入项目目录，也不会修改 Codex 全局配置。

## 7. 完整验证示例

使用 `autovado-goods` 做无业务副作用的验证时：

1. 在 Skill OS 项目管理确认项目已绑定、扫描和应用 Workflow。
2. 在项目详情确认 Profile、Workflow 和 Codex 目录匹配。
3. 在项目内创建一个只写 `specs/` 的 Workflow 接入验证事项。
4. 依次完成 `spec.md`、`plan.md`、`tasks.md` 和 `workflow-state.yaml`。
5. 执行 Workflow Doctor、Profile 状态、Maven 快速检查和 Git 差异保护。
6. 输出交付报告并等待用户验收。
7. 后续真实需求必须创建独立 feature 目录，不要复用验证事项的批准。

验收指定 Codex 会话时，再补两步：

1. 在“会话链路”输入完整会话 ID，确认结果都显示同一个短会话标识。
2. 打开任一 Turn，核对完整会话 ID、工作目录、Token、Skill 命中指数和证据类型；“历史聚合”只能作为兼容证据，不能当作已还原的用户原消息。

## 8. 常见问题

### 扫描成功但没有 Skill 调用

扫描只证明 Skill 文件被发现，不代表 Codex 已经调用。必须从绑定目录启动新的 Codex 任务，并提交与项目相关的真实需求。

### 目录不匹配

关闭当前错误目录的 Codex 任务，从项目根目录重新创建任务，然后在项目详情点击“刷新运行”。

### Profile 需要刷新

项目代码、POM、配置、架构入口或 Mapper 发生变化时，先运行项目 Profile 状态检查，再只刷新受影响模块。

### Workflow 文件冲突

冲突必须先预览和人工处理。推荐 Workflow 不会自动覆盖现有项目规范或业务文件。

### 为什么历史命中不是精确命中

历史会话可能只能按时间和会话聚合。界面会标记“历史聚合/推断”，不能把它当作本次用户消息的精确 Skill 调用。

### 如何得到精确的 Workflow 与 Skill 链路

当前本地 Codex/Claude 会话日志通常只能提供推断证据。精确链路需要一个可信 Adapter 输出符合 `1.0` 协议的本地 JSONL 事件文件，并在“运行监控”中选择该文件导入。

每条精确事件必须带有 Adapter、Harness、项目工作目录、Session、Turn、时间和隐私声明；只接受明确声明未存储原始提示词和输出的事件。导入后在“会话链路”查看 Harness、Adapter、Workflow 模板/节点、Skill 状态、Token 和证据类型。

这不会安装 Hook、修改 Codex/Claude 配置或启动任何任务。桌面端只读取用户明确选择的本地文件。
