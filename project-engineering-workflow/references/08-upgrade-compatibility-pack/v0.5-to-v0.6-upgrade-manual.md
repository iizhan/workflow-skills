# v0.5.x To v0.6.x Upgrade Manual

`0.6.x` adds a source-backed project Profile layer. It remembers verified project facts and confirmed project decisions locally, while preserving task confirmation and permission boundaries.

## Added Capability

- `project-profile-router` as the first workflow gate
- `.specify/project-profile/profile.yaml` for structured stack, architecture, commands, source-of-truth, and engineering facts
- `.specify/project-profile/architecture.md` for human-readable module and critical-flow summaries
- `.specify/project-profile/decision-memory.yaml` for confirmed reusable project choices
- `.specify/scripts/project-profile.mjs` for deterministic `missing / fresh / stale` checks and evidence capture
- `workflow-state.yaml.project_profile` for loaded sections, refreshed evidence, and reused decisions

## Safe Upgrade

1. Run `upgrade --mode capabilities --dry-run --write-report`.
2. Review the new Profile files and existing routing-file changes.
3. Add or reviewed-overwrite the files; do not write business code as part of Profile initialization.
4. Run `node .specify/scripts/project-profile.mjs status --json`.
5. On the first development task, inspect project instructions, manifests, module structure, architecture, data/runtime boundaries, and test/release commands.
6. Write verified facts and unknowns to `profile.yaml` and `architecture.md`, then run `capture --json`.
7. Store only stable confirmed project choices in `decision-memory.yaml`.
8. Run CLI Doctor, shell Doctor, and the generated workflow validator.

## Freshness And Reuse

- `fresh`: reuse relevant Profile sections and matched active decisions; inspect only the requested module.
- `stale`: Refresh only Profile sections implicated by changed manifests, architecture docs, module structure, key entry/config files, or commands.
- `missing`: perform the initial analysis before broad implementation work.
- Repository source of truth always overrides the cache.
- Profile refresh must never copy secrets, raw environment values, private data, or unsupported inference.

## Compatibility

- `0.5.0` projects remain valid without Profile files and receive additive upgrade suggestions.
- Existing `specs/`, durable memory records, and business code are not rewritten by Profile initialization.
- `decision-memory.yaml` cannot approve permissions, deletion, remote writes, publish/push/deploy, scope expansion, release readiness, or final acceptance.
- The ignored `local-state.json` contains evidence fingerprints, not source content.
