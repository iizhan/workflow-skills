# v0.4.x To v0.5.x Upgrade Manual

`0.5.x` adds adaptive backend and frontend role workflows without changing historical `specs/` artifacts or the `fast / standard / controlled` confirmation contract.

## Added Capability

- `project-backend-standards` plus architecture, API, data, runtime/security/observability, testing/delivery, and Java/Spring references
- progressive references under `project-frontend-standards`
- role routing in `AGENTS.md`, Codex/Claude guidance, Doctor contracts, and token/quality evaluation

## Safe Upgrade

1. Run `upgrade --mode capabilities --dry-run --write-report`.
2. Review new role files and proposed updates to existing routing/docs.
3. Add missing files first. Use `--overwrite-existing` only for reviewed existing workflow files.
4. Customize `project-stack-standards` with the repository's real Profile; project facts override generic role references.
5. Run CLI Doctor and shell Doctor.
6. Pilot one backend and one frontend task. Record loaded references, evidence, user corrections, and real provider token usage when available.
7. Adopt `--mode current` and the `0.5.0` marker only after both pilots pass.

## Compatibility

- A project declaring `0.4.0` remains valid without role Workflow files and receives upgrade suggestions.
- A project declaring `0.5.0` must contain the role entries and references and satisfy their content contracts.
- Existing business code, memory records, and historical feature specs are not migration targets.
- Removing old frontend focused skills is not part of this upgrade; JS/React/Vue/CSS skills remain conditional implementation references.

## Rollback

Before adopting the marker, rollback is removal of newly added role files plus restoration of reviewed routing docs. After adopting `0.5.0`, restore the previous workflow files and marker together; do not partially keep a `0.5.0` marker with missing contracts.
