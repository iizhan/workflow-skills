# v0.7.x To v0.8.x Upgrade Manual

`0.8.x` adds declarative Workflow Templates and bounded Scenario Loop Engineering without changing business code, existing `specs/` artifacts, Profile facts, memory records, or historical Workflow Runs.

## Added Capability

- project-local `.skill-os/workflows/*/workflow.yaml` Template declarations;
- a `.skill-os/workflow-registry.yaml` policy file;
- `project-workflow-router` for one-primary scenario selection after Profile and task-lane analysis;
- `workflow-validate` for schema, dependency, Skill reference, DAG, quality, permission and Loop Policy validation;
- seven default Templates: foundation governance, frontend role, backend role, generic feature delivery, design-to-frontend, design-to-API, and Swagger-to-frontend integration;
- bounded Scenario Loop policy: three iterations, two strategies per root cause, scope reconfirmation and budget stop by default.

## Safe Upgrade

1. Run `upgrade --mode capabilities --dry-run --write-report` and review all `.skill-os` and `project-workflow-router` additions.
2. Keep existing `AGENTS.md` custom rules unless the team has reviewed the router insertion; use `--overwrite-existing` only for reviewed workflow files.
3. Run `workflow-validate --output-dir "<project-root>" --json` before declaring the `0.8.2` workflow line.
4. Run `doctor` and confirm the project declares `0.8.2` only after Manifest validation passes.
5. Pilot one new standard or controlled feature. Select one primary scenario Workflow, retain foundation/role Templates as dependencies, and keep all repairs inside the already confirmed scope.

## Compatibility

- `0.7.x` projects remain valid before upgrade. Missing `.skill-os` files only appear as upgrade suggestions.
- `0.8.1` adds `scenario.feature-delivery` additively for ordinary features, fixes, and refactors. It does not alter the six existing Template declarations or their bindings.
- `0.8.2` makes the Codex project conversation the only Scenario Loop execution entry. The desktop workbench only observes imported task evidence and cannot start or authorize a Loop.
- Existing `TASK-06` 1.0 declarations remain readable as `legacy_read_only`; they are never renamed, overwritten, or auto-activated as 1.1 Templates.
- Existing declared graph history remains DAG-shaped. Scenario repair is recorded as a bounded Loop Run containing multiple DAG iterations.
- A quality score of 90 never skips confirmation, verification evidence, a contract failure, a blocking defect, or final user acceptance.
- The project overlay may tighten thresholds, budgets and allowed paths. It cannot grant a new capability, remove a gate, or make a Loop unlimited.

## Rollback

- Restore the reviewed Workflow files and `.specify/workflow-version.txt` from Git or the pre-upgrade backup.
- Remove the new binding or leave the new Templates unselected; this does not alter the project business code.
- Keep the project on `0.7.x` when the team does not accept the router or Loop policy.
- Do not delete historical Workflow Runs, evidence, `specs/`, Profile records or memory to roll back the workflow layer.
