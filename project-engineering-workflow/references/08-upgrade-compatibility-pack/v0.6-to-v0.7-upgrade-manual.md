# v0.6.x To v0.7.x Upgrade Manual

`0.7.x` adds a formal implementation confirmation loop without changing business code or historical delivery artifacts.

## Added Capability

- versioned `设计方案 vN` before formal implementation
- versioned `任务拆解 vN` mapped to `ITEM-*` and verification evidence
- versioned `影响范围 vN` with explicit non-impact boundaries
- one confirmation package covering design, tasks, impact, acceptance, self-test, and rollback
- pause and `vN+1` reconfirmation when material scope or acceptance changes
- post-implementation impact-scope self-check and explicit user acceptance
- `.specify/templates/design-template.md`

## Safe Upgrade

1. Run `upgrade --mode current --dry-run --write-report`.
2. Review `AGENTS.md`, project-local gate skills, templates, and the new design template.
3. Preserve project-specific rules deliberately; use `--overwrite-existing` only for workflow files reviewed by the team.
4. Run `doctor` after the upgrade and confirm the project declares `0.7.0`.
5. Pilot one new or active feature using the full package:
   `设计方案 v1 -> 任务拆解 v1 -> 影响范围 v1 -> 用户确认 -> 实施 -> 自测/影响自查 -> 验证报告 v1 -> 用户验收`.

## Compatibility

- `0.6.x` projects remain valid before upgrade and do not receive hard failures solely because `0.7.x` files are missing.
- Existing `specs/`, business code, tests, Profile facts, decision memory, and session history are not rewritten by the upgrade.
- `fast` work remains lightweight; the new package is mandatory for formal `standard` and `controlled` implementation.
- A material new permission, data path, migration, shared module, release action, user-visible behavior, or acceptance change pauses execution until the delta is confirmed.

## Rollback

- Restore the workflow files changed by the upgrade from Git or the pre-upgrade backup.
- Keep the project at `0.6.x` if the team does not accept the new confirmation gate.
- Do not delete or rewrite feature history to roll back the workflow layer.
