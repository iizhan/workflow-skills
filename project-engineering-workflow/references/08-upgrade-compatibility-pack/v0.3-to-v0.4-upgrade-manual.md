# v0.3.x To v0.4.x Upgrade Manual

`0.4.x` adds adaptive task lanes, versioned confirmation gates, full impact analysis, scope-delta handling, evidence traceability, and explicit user acceptance.

The upgrade changes workflow behavior but does not invalidate historical `specs/<feature>/` artifacts. Old spec, plan, tasks, and workflow-state files remain readable with missing new fields treated as unset.

## 1. Inspect First

```bash
npx @workflow-skills/project-engineering-workflow upgrade \
  --output-dir "/absolute/path/to/project" \
  --mode current \
  --dry-run \
  --write-report
```

Review changes to:

- `AGENTS.md`
- requirement, scope, plan, verification, reporting, session, and upgrade-advisor Skills
- Codex / Claude / architecture docs
- spec, plan, tasks, checklist, workflow-state, reflection, and delivery templates

Do not overwrite project-specific rules blindly.

## 2. Adopt Governance

Merge project-specific wording into the new `fast / standard / controlled` contract, then apply the reviewed governance set:

```bash
npx @workflow-skills/project-engineering-workflow upgrade \
  --output-dir "/absolute/path/to/project" \
  --mode governance \
  --overwrite-existing \
  --write-report
```

Confirm that controlled work now has two gates and fast work is not forced through both.

## 3. Adopt Future-Feature Templates

```bash
npx @workflow-skills/project-engineering-workflow upgrade \
  --output-dir "/absolute/path/to/project" \
  --mode templates \
  --overwrite-existing \
  --write-report
```

This updates templates for future features. It must not rewrite existing `specs/<feature>/` artifacts.

## 4. Mark Current Only After Validation

```bash
npx @workflow-skills/project-engineering-workflow upgrade \
  --output-dir "/absolute/path/to/project" \
  --mode current \
  --overwrite-existing \
  --write-report

npx @workflow-skills/project-engineering-workflow doctor \
  --output-dir "/absolute/path/to/project"
```

Pilot one fast task and one controlled task before making `0.4.x` the team default.

## Acceptance

- fast task: no unnecessary multi-round approval
- controlled task: requirement/impact and child-task plan are separately confirmed
- impact report includes explicit non-impact boundaries
- scope expansion pauses and produces a versioned delta
- verification maps items and impact to evidence
- delivery waits for user acceptance
- dissatisfaction is recorded before any Skill evolution proposal
