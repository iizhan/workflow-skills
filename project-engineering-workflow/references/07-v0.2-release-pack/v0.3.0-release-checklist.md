# v0.3.0 Release Checklist

Use this checklist before publishing `0.3.0`.

## 1. Scope Freeze

- Confirm `0.3.0` is the first release that formally includes branch/release governance.
- Confirm no unfinished breaking refactor is still being bundled into this release.

## 2. Compatibility Review

- Confirm `0.2.x` projects still pass `doctor` without branch/release files.
- Confirm only projects that declare `.specify/workflow-version.txt = 0.3.0` are required to contain the full branch/release file set.

## 3. Git Flow Validation

- Validate `create-feature.sh` creates `feature/<feature-slug>` on a clean repository.
- Validate `prepare-release.sh <version>` creates `release/<version>` and release artifacts from a validated feature branch.
- Validate `finalize-release.sh <version>` creates `v<version>` and merges into `main`.
- Confirm no step silently pushes to the remote.

## 4. Starter Integrity

- Run `npm --prefix project-engineering-workflow run doctor`
- Run `npm --prefix project-engineering-workflow run smoke`
- Run `npm --prefix project-engineering-workflow run pack:dry-run`

## 5. Artifact Review

- Confirm `AGENTS.md` routes branch/release through `project-branch-release`.
- Confirm `workflow-state.yaml` additions are additive and tolerant of older files.
- Confirm release templates and release policy are present.

## 6. Documentation Review

- Confirm `README.md`, `README.zh-CN.md`, and `SKILL.md` explain the `0.3.x` branch/release lane.
- Confirm `docs/AI能力地图.md` and `docs/AI协作架构.md` now show six main lanes.
- Confirm `v0.3.0-release-notes.md` matches the actual shipped behavior.
- Confirm `v0.2-to-v0.3-upgrade-manual.md` matches the actual additive upgrade path.

## 7. Publish Decision

- Confirm `package.json` is set to `0.3.0`.
- Confirm npm auth and publish target are ready.
- Publish only after release notes and checklist are complete.
