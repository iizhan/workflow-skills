# v0.5.0 Release Notes

`0.5.0` adds adaptive frontend and backend engineering role workflows without turning every task into a full lifecycle ceremony.

## Added

- `project-backend-standards` role entry
- backend references for architecture, API/message contracts, data consistency, runtime/security/observability, testing/delivery, and Java/Spring
- progressive frontend references for experience states, architecture/data flow, accessibility/responsive/i18n, performance/security/observability, and testing/delivery
- Project Profile and role routing in AGENTS, Codex, and Claude guidance
- backend and frontend bundle accounting in token evaluation
- backend API/data and frontend journey/layout contract scenarios
- `0.4.x -> 0.5.x` compatibility and upgrade guidance

## Cost Control

- both role entries stay below the 700-token Skill budget
- fast tasks do not load role references
- standard tasks normally load one primary role reference plus testing
- controlled tasks load only references implicated by approved impact
- focused JS/React/Vue/CSS skills remain conditional

## Compatibility

- `0.4.0` projects remain valid without role files and receive additive upgrade suggestions
- `0.5.0` projects require both role contracts and progressive references
- current upgrade preserves historical `specs/` artifacts
- stricter `confirmation_history` and `child_tasks` Doctor requirements begin at `0.5.0`

## Validation Boundary

Static contracts, Doctors, upgrade fixtures, token estimates, and package checks passed. Live blind A/B task replay and provider-level token economics remain required before making best-in-class claims.
