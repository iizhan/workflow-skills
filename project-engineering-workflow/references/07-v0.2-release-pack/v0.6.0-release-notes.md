# v0.6.0 Release Notes

`0.6.0` adds project-aware context reuse to the engineering Workflow.

## Added

- first-gate `project-profile-router`
- structured stack, architecture, commands, source-of-truth, and engineering Profile
- human-readable architecture and critical-flow summary
- confirmed project decision memory with explicit non-approval boundaries
- deterministic evidence fingerprints with `missing / fresh / stale` states
- incremental refresh guidance for changed manifests, module structure, key entry points, configuration, and commands
- `workflow-state.yaml.project_profile` traceability fields
- profile lifecycle task scenario and token bundle accounting

## Behavior

- first use analyzes the project before role-specific development rules run
- later tasks reuse fresh sections instead of rereading the whole repository
- unfamiliar modules still receive scoped onboarding
- stale or conflicting evidence blocks blind reuse and triggers targeted refresh
- Profile refresh does not silently change business code or grant authorization

## Compatibility

- `0.5.0` projects remain valid and receive additive Profile upgrade suggestions
- historical specs, durable memory, and business assets remain untouched by Profile initialization

## Validation Boundary

Static contract coverage, generated `missing -> fresh -> stale` lifecycle checks, Doctors, validator, token budgets, and package checks must pass. Live task replay and provider token economics remain separate evidence requirements.
