# v0.3.1 Release Checklist

Use this checklist before publishing `0.3.1`.

## 1. Scope Freeze

- Confirm `0.3.1` only hardens branch/release governance and does not broaden the workflow surface unexpectedly.
- Confirm no unfinished hotfix-flow refactor is being folded into this patch release.

## 2. Compatibility Review

- Confirm `0.3.0` projects are not forced to adopt `release-doctor.sh` until they intentionally upgrade.
- Confirm `0.2.x` projects still pass `doctor` without branch/release files.

## 3. Release Surface Validation

- Validate `project-engineering-workflow release-doctor --output-dir ... --release-version ...` returns structured blockers and warnings.
- Validate `bash .specify/scripts/bash/release-doctor.sh <version>` fails closed when release assets are missing.
- Confirm `prepare-release.sh` and `finalize-release.sh` reject extra push/publish-style arguments.
- Confirm no shipped release script silently pushes to the remote or publishes to npm.

## 4. Starter Integrity

- Run `npm --prefix project-engineering-workflow run doctor`
- Run `npm --prefix project-engineering-workflow run smoke`
- Run `npm --prefix project-engineering-workflow run pack:dry-run`

## 5. Artifact Review

- Confirm `release-doctor.sh` ships in the template and package tarball.
- Confirm release policy and release checklist now mention explicit approval for remote push / publish.
- Confirm `workflow-version.txt` is `0.3.1`.

## 6. Documentation Review

- Confirm `README.md`, `README.zh-CN.md`, and `SKILL.md` explain `release-doctor`.
- Confirm `v0.3.1-release-notes.md` matches actual shipped behavior.
- Confirm implementation notes no longer describe release-doctor as missing.

## 7. Publish Decision

- Confirm `package.json` is set to `0.3.1`.
- Confirm npm auth and publish target are ready.
- Publish only after release notes and checklist are complete.
