# v0.3.1 Release Notes

## Release Position

This patch release hardens the governed branch and release lane introduced in `0.3.0`.

Package version for this release is `0.3.1`.

## Summary

`0.3.1` keeps the `0.3.0` workflow shape, but closes two practical release gaps:

- release readiness now has a dedicated doctor surface
- local release scripts now explicitly refuse accidental remote push or publish flags

This means branch/release governance is no longer only a set of scripts and templates. It now has a machine-readable release health check and a clearer boundary between local release prep and external publication.

## Added

- Added `project-engineering-workflow release-doctor`.
- Added `bash .specify/scripts/bash/release-doctor.sh <version>` to generated projects.
- Added structured `--json` and `--json-out` output for release-doctor runs.
- Added release-doctor validation for:
  - missing branch/release workflow assets
  - dirty git worktrees
  - missing main branch
  - missing release artifacts under `specs/releases/<version>/`
  - release branch presence
  - manual-only remote action guard status

## Changed

- Updated `prepare-release.sh` and `finalize-release.sh` to reject extra push/publish-style arguments.
- Updated release policy and checklist templates to require explicit approval for remote push or npm publish.
- Updated package docs and skill docs so consumers can discover release-doctor as part of the official branch/release surface.
- Updated doctor compatibility rules so `0.3.1` projects expect the new `release-doctor.sh` asset as part of the current workflow line.

## Compatibility

- `0.3.1` remains additive within the `0.3.x` line.
- Existing `0.3.0` projects can keep running unchanged until they explicitly adopt the new release-doctor script.
- Older `0.2.x` projects are still not forced into branch/release governance.
- Remote push and npm publish remain explicit manual steps outside the local release scripts.

## Validation

This release should be validated with:

- `node --check bin/project-engineering-workflow.mjs`
- `npm run doctor`
- `npm run smoke`
- `npm run pack:dry-run`
- a temporary git repo that verifies:
  - release-doctor fails before release assets exist
  - `prepare-release.sh` creates local release artifacts without any remote action
  - release-doctor passes once release assets exist
  - `finalize-release.sh` creates a local tag and merge without remote push

## Recommended Follow-Up

- define a hotfix branch contract
- add a dedicated publish checklist for package registries beyond npm
- consider a future release artifact diff report for multi-package repos
