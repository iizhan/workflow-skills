# v0.2.0 Candidate Change Summary

## Release Position

Current `package.json` version is `0.2.0`.

This document describes the `v0.2.0` release scope and the pre-publish packaging state.

## Summary

The proposed `v0.2.0` milestone upgrades the starter from a project workflow baseline into a workflow system with:

- governed memory
- governed framework evolution
- structured end-of-task reflection
- structured user-facing final delivery output
- onboarding and real-task reference material

## Major Additions

### 1. Memory Governance

Added a dedicated memory lane with:

- `project-memory-router`
- `memory-policy.md`
- session reflection fields in `workflow-state.yaml`

Outcome:

- memory is no longer implicit chat residue
- durable memory now has scope, retention, and confirmation rules

### 2. Framework Evolution Governance

Added a dedicated evolution lane with:

- `project-evolution-router`
- `evolution-policy.md`
- `evolution-prefill-policy.md`
- `evolution-draft-protocol.md`
- `rule-change-proposal.md`

Outcome:

- repeated learnings can be promoted into explicit rule proposals
- framework changes now require proposal, confirmation, validation, and rollback paths

### 3. Reflection Artifacts

Added structured task reflection support with:

- `task-reflection.md`
- `reflection-output-protocol.md`
- `reflection_artifacts` in `workflow-state.yaml`

Outcome:

- end-of-task learnings can be recorded in a stable, reviewable format
- reflection data can directly feed memory and evolution lanes

### 4. Final Output Schema

Added structured user-facing closeout support with:

- `delivery-summary.md`
- `final-output-protocol.md`
- `delivery_artifacts` in `workflow-state.yaml`
- updated `project-test-and-report`

Outcome:

- final Chinese delivery output now has a standard schema
- verification, user choices, risks, and follow-up are unified in one closeout artifact

### 5. Onboarding And Reference Layer

Added onboarding and examples with:

- `docs/AI能力地图.md`
- `references/06-real-task-example-pack/`
- this `references/07-v0.2-release-pack/`

Outcome:

- onboarding is easier for new teammates
- teams can review filled examples before using the workflow in real tasks

## Upgrade Impact

For existing consumers of the starter, `v0.2.0` mainly changes:

- workflow governance
- artifact completeness
- documentation and onboarding

It does not force a business-code architecture rewrite.
It should also remain backward-compatible for older generated workflow artifacts inside the `0.2.x` line.

## Residual Gaps Before A Full Release

- proposal and summary files are standardized, but not yet auto-filled by scripts
- memory and evolution are governed by protocol, but not yet backed by persistent storage tooling
- example packs exist, but more domain-specific examples may still help adoption
