# v0.2.0 Candidate Release Checklist

Use this checklist before changing the package version or publishing the package.

## 1. Scope Freeze

- Confirm the `v0.2.0` milestone includes only workflow-layer additions already agreed on.
- Confirm no unfinished large refactor is still being folded into this release.
- Confirm whether the release is a public publish or just an internal milestone tag.

## 2. Starter Integrity

- Run `npm --prefix project-engineering-workflow run doctor`
- Run `npm --prefix project-engineering-workflow run smoke`
- Confirm the generated smoke project contains:
  - `docs/AI能力地图.md`
  - `task-reflection.md`
  - `rule-change-proposal.md`
  - `delivery-summary.md`
  - memory and evolution protocol files

## 3. Artifact Review

- Review `AGENTS.md` for workflow order consistency.
- Review `.specify/memory/*` for overlapping or conflicting guidance.
- Review `.specify/templates/*` for placeholder correctness.
- Review `project-test-and-report/SKILL.md` for final-output alignment.
- Review compatibility rules and confirm new workflow files are additive for existing projects.

## 4. Documentation Review

- Confirm `project-engineering-workflow/README.md` and `README.zh-CN.md` reflect the new lanes.
- Confirm `docs/AI协作架构.md` and `docs/AI能力地图.md` are consistent.
- Confirm `docs/升级兼容策略.md` matches the intended semver and migration posture.
- Confirm `references/06-real-task-example-pack/` still matches the current workflow.
- Confirm this `references/07-v0.2-release-pack/` still matches the actual release scope.

## 5. Packaging Review

- Run `npm --prefix project-engineering-workflow run pack:dry-run`
- Inspect the package contents for:
  - `assets/`
  - `bin/`
  - `references/`
  - `scripts/`
- Confirm the package does not accidentally omit new workflow files.

## 6. Versioning Decision

- Confirm `project-engineering-workflow/package.json` is set to `0.2.0`.
- If the release is postponed after version bump, treat this pack as pre-publish release preparation and avoid publishing until approval returns.

## 7. Publish Decision

- If publishing publicly:
  - run `npm --prefix project-engineering-workflow run publish:public`
- If not publishing:
  - record the milestone in project notes or tag planning only

## 8. Post-Release Follow-Up

- Decide whether `v0.3.0` should focus on automation scripts for prefill and final-output generation.
- Decide whether memory persistence tooling belongs in the next milestone.
- Decide whether more real-task example packs are needed for onboarding.
- Decide whether a dedicated migration helper is needed before any future breaking major release.
