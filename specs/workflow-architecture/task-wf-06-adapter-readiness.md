# TASK-WF-06：Adapter 就绪诊断与精确观测预览

**状态**: 已完成并验收  
**日期**: 2026-07-22  
**依赖**: TASK-WF-03 Harness Adapter 协议、TASK-WF-04 可观察性、TASK-WF-05 受控事件接入  
**影响等级**: medium

## 目标

让用户在单个项目的运行监控中明确知道三件相互独立的事实：

1. 项目是否已安装可读取的 skills-workflow；
2. Codex 会话来源和当前工作目录是否可观测、是否匹配；
3. Skill 目前是仅可发现、日志推断路由/调用，还是已收到精确 Adapter 事件。

这样“已连接待触发”“已配置待连接”等综合标签不再混淆安装、连接和调用事实。

## 已交付范围

- 新增只读 `AdapterReadinessService`，复用本地 Codex 来源发现、工作流 Doctor 和 Trace 数据，输出：
  - 接入状态：`not_installed`、`installed`、`invalid`、`read_only`；
  - 连接状态：会话来源、目录匹配、最近会话、过期证据与授权错误；
  - Skill 观测状态：可用、推断路由、推断调用、精确调用、精确完成和失败。
- 在项目详情的“运行监控”加入紧凑状态面板、精确/推断证据计数、刷新检查和可展开的精确观测预览。
- 预览明确列出：当前仅支持用户选择的已脱敏 Protocol 1.0 JSONL 文件导入；“前往导入遥测”只关闭详情并定位到“分析 / 遥测”的文件选择区域，实际导入仍须由用户确认。本版本不写项目目录、不安装 Hook、不启动 App Server、不修改 Codex 全局配置。
- 只有真实 `capture_mode: precise` 且 Skill 有明确调用或终态事件时，才显示精确观测；日志推断不会升级为精确状态。

## 明确不做

- 不安装或修改 `~/.codex` 内的任何全局配置。
- 不为用户注册 Hook、App Server、后台进程或自动化 Adapter。
- 不启动 Codex/Claude、Shell、项目脚本或模型任务。
- 不将目录匹配、Skill 文件存在或日志推断表述为精确调用。

## 验收

- 项目已安装、Codex 来源、目录匹配和 Skill 证据可以独立阅读。
- 会话源不可用、目录不匹配、未授权、仅推断和精确完成均有不同状态。
- 点击“重新检查”只运行本地只读诊断；不会产生项目文件或全局配置写入。
- 精确观测预览明确显示无写入边界、当前可用的 JSONL 导入路径、自动安装未启用原因和取消点；前往导入时，项目详情关闭且遥测文件选择器处于可见区域。

## 验证证据

- `npm run test:adapter-readiness`：覆盖只读保证、推断与精确分层、精确完成、来源不可用和无全局配置写入预览。
- `npm run self-test:ui`：覆盖项目详情运行监控、三维状态、精确观测预览和无横向溢出。
- `npm run typecheck`、`npm run build`、`git diff --check`。
